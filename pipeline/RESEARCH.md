# Game Asset Library — Research Notes

Researched 2026-11-09 for an agent-searchable, original 2D game-asset library. Focus: consistent AI generation, metadata/taxonomy, and discoverability (SQLite FTS, manifests, later embeddings). This is a working brief, not a legal opinion.

## (a) AI game-asset generation

Consistency is the actual problem, not a single good image. Current practice is to lock a **style sheet** (art style, perspective, grid/sprite size, outline rule, light direction, limited palette, flat keyable background) and paste it unchanged into every prompt, changing only the subject. [Cyborb](https://cyborb.ai/blog/ai-game-assets), [SpriteLab](https://www.sprite-lab.com/guides/how-to-keep-ai-game-art-consistent), [Elseland](https://www.elseland.ai/blog/ai-pixel-art-game-assets)

Practical rules:

- **One style pack per coherent set.** Do not mix side-view heroes with top-down enemies, or 16px tiles with 32px tiles scaled differently. Pick one pixel density and one scale for a pack.
- **Reference the winners.** After a few accepted assets exist, feed 1–3 of them back as style references so later images inherit palette, outline weight and lighting rather than drifting. Generate related assets together (a 4×4 icon sheet in one image) so they share lighting and line weight. [Cyborb](https://cyborb.ai/blog/ai-game-assets), [Ludo.ai tilesets](https://ludo.ai/docs/sprite-generator/tilesets)
- **Seeds / templates, not vibes.** Keep a prompt template and (where the generator allows) a fixed seed family per pack. This library locks a `style_prefix` and palette per pack. The Cursor `GenerateImage` tool has no public seed parameter, so consistency has to come from the prefix, palette, references, and post-process snap.
- **Transparent backgrounds.** Do not trust a model to emit real alpha. Some draw a checkerboard that only looks transparent. Generate on a flat color that does not appear in the art (typically magenta `#FF00FF`), then chroma-key with a small fuzz, and clean fringe/despill. For pixel art, snap to the palette *before* dropping the key color, so edges stay hard. [Cyborb](https://cyborb.ai/blog/ai-game-assets)
- **Pixel art post.** Most “pixel art” from image models is a large soft painting of pixels. The reliable recipe is: nearest-neighbor shrink to the real grid (16/32/64), remap onto the locked palette with no dither, then inspect at native size and at 400%. Preview with nearest-neighbor only; bilinear hides broken pixels. [Cyborb](https://cyborb.ai/blog/ai-game-assets), [Elseland](https://www.elseland.ai/blog/ai-pixel-art-game-assets), [SpriteLab](https://www.sprite-lab.com/guides/how-to-keep-ai-game-art-consistent)
- **Tilesets and seamless textures.** Prompt for a *surface*, not a scene. Ask for “seamless tileable, even lighting, top-down.” Then verify: tile in a 3×3 and roll the texture by half so old seams meet in the middle. AI edges often *almost* match; transition/autotile tiles still need hand work or engine autotiles. Keep one reference terrain for the whole set so palettes do not drift. [Sprite AI — seamless tiles](https://www.sprite-ai.art/guides/seamless-tiles), [Ludo.ai](https://ludo.ai/docs/sprite-generator/tilesets), [Cyborb](https://cyborb.ai/blog/ai-game-assets)
- **Icons and UI kits.** Strongest AI use case. Generate a whole set in one grid (“one item per cell, nothing crossing borders, no labels”). Slice on a regular grid, key the background, and QA at the real UI size (a 256px icon can collapse at 48px). [Cyborb](https://cyborb.ai/blog/ai-game-assets)
- **Characters and turnarounds.** AI is only fair at character sprites and weak at animation (features drift frame to frame). Prefer a 2×2 turnaround (front, three-quarter, side, back) in one image so proportions stay shared; animation is better done by editing one approved key pose than by fresh generations. Keep a shared baseline / foot pivot. [Cyborb](https://cyborb.ai/blog/ai-game-assets)
- **VFX.** Generate short frame strips or a 2×2/4×4 of one effect in one image. Same canvas size and anchor (usually center) on every frame.
- **Backgrounds and parallax.** Generate each layer separately (sky, far, mid, near) with a shared palette and horizon line, not a finished poster. 16:9 is a good default for wide scenes.
- **What AI is good and bad at** (Cyborb, Sep 2026): icons/props/textures strong; backgrounds good; character sprites fair (cleanup); tilesets fair (seams); animation frames weak.
- **Licensing / shipping.** Never prompt for existing characters, logos, or a living artist’s name. Raw AI output has limited US copyright protection; hand edits, selection, and arrangement are firmer ground. Steam asks for disclosure of AI content that ships with or is generated by a game. [Cyborb](https://cyborb.ai/blog/ai-game-assets) citing [USCO AI report Part 2 (Jan 2025)](https://www.copyright.gov/ai/) and [Steamworks Content Survey](https://partner.steamgames.com/doc/store/review_process)

## (b) Metadata standards and taxonomy

There is no single industry metadata standard for loose 2D assets, but three conventions are widely used:

**OpenGameArt tags** ([Art Tags guide](https://opengameart.org/content/art-tags)): tags exist to narrow search. Prefer several **singular**, comma-separated, mostly single-word tags (`sword`, not `swords`). Put style (`pixelart`, `painterly`), perspective (`isometric`, `sidescroller`, `overhead`, `3/4`), technical specs (`32x32`, `8-bit`, palette names), subject words, and file format **with the dot** (`.png`). Do **not** tag license or the broad category — those are separate fields. License lives in its own column so it can be filtered exactly.

**Kenney pack layout** ([kenney.nl/support](https://kenney.nl/support), [tilemap import guide](https://kenney.nl/knowledge-base/game-assets-2d/importing-and-using-tilemaps), [itch examples](https://kenney-assets.itch.io/monster-builder-pack)): packs group by kind (2D sprites/tiles, UI, icons, VFX, textures). Many 2D packs ship both a packed sheet and individual sprites, plus a small `tilemap.txt` of tile width, height and spacing. Names should be semantic (`icon_health_potion.png`), not only `tile_0123.png`. License is declared once per pack (Kenney uses CC0; this library uses a project license field). itch listings expose category, tags, license, author, and “generative AI used?” — useful fields to keep even for a private library.

**Sprite-sheet / atlas metadata.** Liberated Pixel Cup discussed an open sheet format years ago ([LPC thread](https://lpc.opengameart.org/forumtopic/open-sprite-sheet-metadata-format)). In practice, **TexturePacker JSON Hash / JSON Array** is the interchange engines already read (Pixi, Phaser, Unity importers). Per-sprite fields: `frame {x,y,w,h}`, `rotated`, `trimmed`, `spriteSourceSize`, `sourceSize`, optional `pivot {x,y}` normalized 0–1 relative to *untrimmed* `sourceSize`. `(0.5, 0.5)` is center; characters often use `(0.5, 1.0)` at the feet. [TexturePacker / CodeAndWeb explanation](https://gamedev.stackexchange.com/questions/115982/industry-standard-json-formats-for-game-assets), [FastPack pivots](https://www.mintlify.com/Hexeption/FastPack/features/pivot-points)

**Recommended record (this library):** identity and paths; category / subcategory / subject / style pack; tags JSON (OGA-style, singular); natural-language description; full prompt plus style prefix and negative; width/height; `has_alpha`; palette and dominant colors; `tileable`; pivot; frame/atlas info; license; generator; created_at; sha256; perceptual hash; QA status. That covers search, provenance, and engine import.

## (c) Agent discoverability

Patterns that work for people *and* agents:

- **SQLite + FTS5** as the catalog: one `assets` row per file, WAL mode, short transactions, a busy timeout. FTS5 over description, tags, subject (and category/style for phrase queries). Filter with ordinary columns (category, style, size, alpha, tileable, license, status). This is how projects like [Spritefield](https://devanmetz.com/portfolio/spritefield/) (12.7k+ assets, weighted FTS5 + OpenAPI + MCP-style tools), photo libraries ([PrivateLens architecture](https://github.com/kenny2077/PrivateLens/blob/main/docs/architecture.md), [Local Lens schema](https://deepwiki.com/kevin93203/local-lens/4.1-sqlite-database-schema)) and similar indexes are built.
- **JSON / JSONL manifests** beside the database so agents can grep or stream records without SQL. A stable relative path is load-bearing — treat paths as an API ([Kenney-on-disk lesson](https://github.com/shorepine/kenney)).
- **Embeddings later, not on this box.** CLIP / text embeddings (often 512-d OpenCLIP, stored in `sqlite-vec` or a side table) give semantic search (“rusty dagger” vs exact tag `dagger`). Hybrid search is FTS first, vector fallback, then metadata filters. Running CLIP here would be a heavy model; the schema reserves an `embeddings` table and the work is documented as an **Orbit bee follow-up**.
- **A small query surface beats a dump.** CLI and a read-only HTTP API (search + get-by-id + health, OpenAPI-like query params) are enough for agents. Spritefield exposes `search_assets`-style tools and paginated cursors; we follow that idea without the hosted stack.
- **Parallel writers.** For multi-worker generation: WAL, `BEGIN IMMEDIATE` around claims, a claims/lease table so stale work can be reclaimed, and per-worker staging directories so slicing does not collide. Progress should be snapshotted from the database, not from a racy JSON file used as the source of truth.

## Decisions for this library

1. Seven named style packs, each with a locked prefix, palette, perspective, and target sizes.
2. Generate **sheets** (4×4 icons/UI, 2×2 character turnarounds, VFX strips) and **singles** for tileable textures and backgrounds.
3. Magenta key + Pillow/numpy post (trim, canvas snap, pixel nearest-neighbor + palette remap, thumbs, palette extract, dHash dedupe, QA flags). No heavy ML on the box.
4. SQLite `assets.db` (WAL) + FTS5 + `specs`/`batches`/`claims` for resumable sharded generation + `manifest.jsonl`.
5. License field on every row: `original, generated for Kyle Durepos`. Original designs only; no real people; no trademarked characters or third-party IP in prompts.
6. CLIP embeddings explicitly deferred to an Orbit bee.
